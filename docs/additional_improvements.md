### 1. **Дополнительные технические индикаторы**

#### RSI (Relative Strength Index)
**Зачем:** Определение перекупленности/перепроданности
- RSI > 70 → перекупленность → сигнал на продажу
- RSI < 30 → перепроданность → сигнал на покупку
- RSI 30-70 → нейтральная зона

**Реализация:**
```python
def calculate_rsi(candles: pd.DataFrame, period: int = 14) -> Optional[float]:
    # pandas-ta уже поддерживает: ta.rsi(close, length=14)
    rsi = ta.rsi(candles['close'], length=period)
    return float(rsi.iloc[-1]) if not rsi.empty else None
```

**Сигналы:**
- `RSI_OVERSOLD` (RSI < 30) → +0.5 к score BUY
- `RSI_OVERBOUGHT` (RSI > 70) → -0.5 к score SELL

---

#### MACD (Moving Average Convergence Divergence)
**Зачем:** Определение изменения тренда
- MACD линия пересекает сигнальную снизу вверх → бычий сигнал
- MACD линия пересекает сигнальную сверху вниз → медвежий сигнал

**Реализация:**
```python
def calculate_macd(candles: pd.DataFrame) -> Dict[str, Optional[float]]:
    macd = ta.macd(candles['close'])
    return {
        'macd': macd['MACD_12_26_9'].iloc[-1],
        'macd_signal': macd['MACDs_12_26_9'].iloc[-1],
        'macd_histogram': macd['MACDh_12_26_9'].iloc[-1]
    }
```

**Сигналы:**
- `MACD_BULLISH_CROSS` → +0.4 к score BUY
- `MACD_BEARISH_CROSS` → -0.4 к score SELL

---

#### Bollinger Bands
**Зачем:** Определение волатильности и экстремальных цен
- Цена касается нижней полосы → возможная покупка
- Цена касается верхней полосы → возможная продажа
- Сужение полос → низкая волатильность (перед большим движением)

**Реализация:**
```python
def calculate_bollinger_bands(candles: pd.DataFrame, period: int = 20, std: float = 2.0):
    bb = ta.bbands(candles['close'], length=period, std=std)
    return {
        'bb_upper': bb[f'BBU_{period}_{std}'].iloc[-1],
        'bb_middle': bb[f'BBM_{period}_{std}'].iloc[-1],
        'bb_lower': bb[f'BBL_{period}_{std}'].iloc[-1],
        'bb_width': (bb[f'BBU_{period}_{std}'].iloc[-1] - bb[f'BBL_{period}_{std}'].iloc[-1]) / bb[f'BBM_{period}_{std}'].iloc[-1] * 100
    }
```

**Сигналы:**
- `PRICE_NEAR_BB_LOWER` → +0.3 к score BUY
- `PRICE_NEAR_BB_UPPER` → -0.3 к score SELL
- `BB_SQUEEZE` (узкие полосы) → дополнительный сигнал

---

#### ATR (Average True Range)
**Зачем:** Измерение волатильности для адаптивных порогов
- Высокий ATR → высокая волатильность → нужен больший порог изменения
- Низкий ATR → низкая волатильность → меньший порог достаточен

**Применение:**
- Для облигаций: использовать ATR для определения порога (облигации менее волатильны)
- Адаптивные пороги уведомлений: если ATR высокий, увеличить порог изменения цены

### 2. **Улучшенный анализ объёма**

#### Volume Profile (профиль объёма)
**Зачем:** Понимание, где сосредоточен объём торгов
- Высокий объём на определённых уровнях цен → поддержка/сопротивление

#### On-Balance Volume (OBV)
**Зачем:** Подтверждение тренда объёмом
- OBV растёт вместе с ценой → тренд подтверждён
- OBV падает при росте цены → расхождение, возможный разворот

#### Volume-Weighted Average Price (VWAP)
**Зачем:** Справедливая цена с учётом объёма
- Цена выше VWAP → бычий сигнал
- Цена ниже VWAP → медвежий сигнал

---

### 3. **Адаптивные пороги и фильтры**

#### Учёт волатильности инструмента
**Проблема:** Фиксированный порог 3% не подходит для всех инструментов
- Волатильные акции (например, AFLT) → порог 5%
- Стабильные акции (SBER) → порог 2-3%
- Облигации → порог 1-2%

**Решение:**
```python
def get_adaptive_threshold(symbol: str, atr: float, base_threshold: float = 3.0) -> float:
    # Используем ATR для адаптации порога
    volatility_multiplier = atr / base_threshold
    return base_threshold * volatility_multiplier
```

#### Фильтр по времени торгов
**Проблема:** Изменения в нерабочее время могут быть шумом
- Игнорировать изменения вне торговых часов (10:00-18:45 МСК)
- Или использовать меньший вес для изменений вне торгов

### 5. **Контекстный анализ**

#### Корреляция между инструментами
**Зачем:** Понимание общего тренда рынка
- Если все банки падают → возможно общий тренд сектора
- Если только один инструмент падает → возможно специфическая проблема

**Применение:**
- Группировать инструменты по секторам
- Учитывать общий тренд сектора при анализе отдельного инструмента

#### Рыночные индексы
**Зачем:** Контекст общего рынка
- MOEX индекс падает → более осторожные сигналы на покупку
- MOEX индекс растёт → более агрессивные сигналы

### 6. **Улучшенная обработка облигаций**

#### Duration и Convexity
**Зачем:** Понимание чувствительности к изменению ставок
- Высокий Duration → высокая чувствительность к ставкам
- Convexity → нелинейная зависимость

#### Spread (спред доходности)
**Зачем:** Сравнение с эталоном (ОФЗ)
- Высокий спред → выше риск → выше доходность
- Низкий спред → низкий риск → низкая доходность

#### Кривая доходности
**Зачем:** Понимание ожиданий рынка
- Нормальная кривая → ожидание роста
- Инвертированная кривая → ожидание падения

### 8. **Улучшенная система уведомлений**

#### Приоритизация уведомлений
**Проблема:** Много уведомлений → шум

**Решение:**
- Группировать по приоритету (HIGH/MEDIUM/LOW)
- Отправлять HIGH сразу, MEDIUM группировать, LOW только в сводке
- Дедупликация (не отправлять одно и то же дважды)

#### Контекстные уведомления
**Пример:**
```
📉 SBER: Цена снизилась на 4.2%
📊 Объём: 2.3x от среднего
📈 RSI: 28 (перепроданность)
💡 Рекомендация: Сильный сигнал на покупку
⚠️ Контекст: Все банки падают (общий тренд сектора)
```

### 9. **Персонализация**

#### Профиль риска пользователя
**Зачем:** Разные пороги для разных пользователей

**Типы профилей:**
- Консервативный: высокие пороги, только сильные сигналы
- Умеренный: средние пороги
- Агрессивный: низкие пороги, больше сигналов

#### Цели инвестирования
- Дивидендная стратегия → больше веса DY
- Ростовая стратегия → больше веса трендам
- Сбалансированная → равные веса

### 10. **Мониторинг и метрики системы**

#### Отслеживание точности сигналов
**Зачем:** Понимание, насколько точны наши рекомендации

**Метрики:**
- Сколько сигналов BUY привело к росту цены через N дней
- Сколько сигналов SELL предотвратило падение
- Средняя доходность по сигналам

#### A/B тестирование алгоритмов
- Тестировать разные веса сигналов
- Сравнивать результаты
- Выбирать лучший вариант
