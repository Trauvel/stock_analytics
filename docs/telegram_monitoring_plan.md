# План улучшения системы анализа с Telegram-уведомлениями

## 📊 Текущее состояние системы

### Что уже есть:
1. **Метрики:**
   - SMA (20/50/200 дней)
   - 52W диапазон (high/low)
   - Дивидендная доходность (DY)
   - Объём торгов (volume)
   - Технические сигналы (Golden Cross, Death Cross, etc.)

2. **Рекомендации:**
   - BUY/HOLD/SELL на основе scoring системы
   - Учёт дивидендов, трендов, позиции относительно SMA200

3. **Обновление данных:**
   - Раз в день (19:10 МСК)
   - Полный анализ всех тикеров

### Что нужно добавить:
1. **Частое обновление данных** (каждые 3-4 часа)
2. **История изменений** (сравнение с предыдущими значениями)
3. **Telegram-бот** для уведомлений
4. **Умные триггеры** на основе изменений цены и объёма

---

## 🎯 Цели системы

1. **Мониторинг изменений цены:**
   - Отслеживание значимых изменений цены (например, ±3-5%)
   - Сравнение с предыдущими значениями (3-4 часа назад, 24 часа назад)
   - Учёт объёма торгов для подтверждения сигналов

2. **Уведомления в Telegram:**
   - "📉 Цена снизилась на X%, объём высокий → можно докупать"
   - "📈 Цена выросла на X%, объём высокий → можно продавать"
   - "⚠️ Значительное изменение объёма без изменения цены"

3. **Персонализация:**
   - Уведомления только по инструментам из портфеля
   - Настройка порогов для каждого инструмента
   - Фильтрация по типу инструмента (акции/облигации)

---

## 📋 План реализации (по этапам)

### Этап 1: История изменений (Price History Tracking)

**Цель:** Сохранять историю цен и метрик для сравнения

**Задачи:**
1. Создать модель данных для истории:
   ```python
   PriceSnapshot:
     - symbol: str
     - timestamp: datetime
     - price: float
     - volume: float
     - sma_20, sma_50, sma_200: Optional[float]
     - dy_pct: Optional[float]
   ```

2. Создать репозиторий для хранения истории:
   - `PriceHistoryRepository` (DDD)
   - Хранение в БД (SQLite/PostgreSQL) или файлах (JSON/Parquet)
   - Индексация по symbol + timestamp

3. Модифицировать процесс обновления:
   - После получения данных с MOEX сохранять snapshot
   - Хранить последние N дней (например, 30 дней)
   - Автоматическая очистка старых данных

**Файлы для создания/изменения:**
- `app/domain/price_history/entities/price_snapshot.py`
- `app/domain/price_history/repositories/price_history_repository.py`
- `app/infrastructure/persistence/repositories/price_history_repository_impl.py`
- `app/process/report.py` - добавить сохранение snapshot после обработки

**Оценка:** 2-3 часа

### Этап 2: Частое обновление данных (3-4 часа)

**Цель:** Запрашивать данные с MOEX каждые 3-4 часа

**Задачи:**
1. Создать новый планировщик для частых обновлений:
   - Отдельный от ежедневного полного анализа
   - Запуск каждые 3-4 часа (например, 9:00, 13:00, 17:00, 21:00)
   - Обновление только тикеров из портфеля (не всех)

2. Оптимизация запросов:
   - Кэширование данных (если цена не изменилась значительно)
   - Batch-запросы (если API поддерживает)
   - Rate limiting (уважение к лимитам MOEX)

3. Логирование:
   - Отслеживание успешных/неуспешных обновлений
   - Метрики времени выполнения

**Файлы для создания/изменения:**
- `app/scheduler/frequent_updates_job.py` - новый планировщик
- `app/main.py` - добавить второй планировщик
- `app/process/quick_update.py` - быстрый обновление без полного анализа

**Оценка:** 2-3 часа

---

### Этап 3: Анализ изменений (Change Detection)

**Цель:** Определять значимые изменения и генерировать сигналы

**Задачи:**
1. Создать сервис для анализа изменений:
   ```python
   ChangeAnalyzer:
     - compare_with_previous(symbol, hours_ago=3) -> ChangeResult
     - detect_significant_changes() -> List[ChangeSignal]
   ```

2. Критерии значимых изменений:
   - **Изменение цены:**
     - Снижение > 3% за 3-4 часа → сигнал "можно докупать"
     - Рост > 3% за 3-4 часа → сигнал "можно продавать"
     - Снижение > 5% за 24 часа → сильный сигнал "докупать"
     - Рост > 5% за 24 часа → сильный сигнал "продавать"
   
   - **Изменение объёма:**
     - Объём > 2x от среднего за последние 5 дней → подтверждение сигнала
     - Высокий объём + изменение цены → усиление сигнала
   
   - **Технические индикаторы:**
     - Цена пересекла SMA20/50 → дополнительный сигнал
     - Изменение DY (для акций) → сигнал

3. Приоритизация сигналов:
   - HIGH: изменение > 5% + высокий объём
   - MEDIUM: изменение 3-5% + средний объём
   - LOW: изменение 1-3% или без объёма

**Файлы для создания:**
- `app/domain/price_history/services/change_analyzer.py`
- `app/domain/price_history/value_objects/change_signal.py`
- `app/application/price_history/analyze_changes_use_case.py`

**Оценка:** 3-4 часа

### Этап 4: Telegram-бот интеграция

**Цель:** Отправлять уведомления в Telegram

**Задачи:**
1. Создать Telegram-бот:
   - Использовать библиотеку `python-telegram-bot` или `aiogram`
   - Настройка через переменные окружения (BOT_TOKEN, CHAT_ID)
   - Команды: `/start`, `/status`, `/portfolio`, `/settings`

2. Форматирование сообщений:
   ```
   📉 SBER: Цена снизилась на 4.2% (было 280₽ → стало 268₽)
   📊 Объём: 2.3x от среднего (высокий)
   💡 Рекомендация: Можно докупать
   ⏰ Время: 13:45 МСК
   ```

3. Настройки уведомлений:
   - Включить/выключить уведомления для каждого инструмента
   - Настройка порогов (минимальное изменение для уведомления)
   - Фильтр по типу сигнала (только BUY, только SELL, или все)

4. Интеграция с системой изменений:
   - После анализа изменений → отправка уведомлений
   - Группировка уведомлений (не спамить)
   - Дедупликация (не отправлять одно и то же дважды)

**Файлы для создания:**
- `app/infrastructure/telegram/bot.py` - основной бот
- `app/infrastructure/telegram/notifier.py` - отправка уведомлений
- `app/application/telegram/send_notification_use_case.py`
- `.env.example` - добавить BOT_TOKEN, CHAT_ID

**Зависимости:**
- `python-telegram-bot` или `aiogram`

**Оценка:** 4-5 часов

---

### Этап 5: Конфигурация и настройки

**Цель:** Настраиваемые пороги и фильтры

**Задачи:**
1. Конфигурационный файл:
   ```yaml
   telegram:
     enabled: true
     bot_token: ${TELEGRAM_BOT_TOKEN}
     chat_id: ${TELEGRAM_CHAT_ID}
   
   monitoring:
     update_interval_hours: 3
     price_change_threshold_pct: 3.0  # Минимальное изменение для уведомления
     volume_spike_threshold: 2.0      # Порог всплеска объёма
     compare_periods:
       - hours: 3
       - hours: 24
   
   notifications:
     only_portfolio: true              # Только инструменты из портфеля
     min_confidence: "MEDIUM"          # Минимальная уверенность сигнала
     group_notifications: true         # Группировать уведомления
   ```

2. UI для настройки (опционально):
   - Страница в веб-интерфейсе для настройки уведомлений
   - Включение/выключение для каждого инструмента
   - Настройка порогов

**Файлы для создания/изменения:**
- `config/monitoring.yaml` - новый конфиг
- `app/config/loader.py` - загрузка конфига мониторинга
- `static/settings.html` - добавить секцию Telegram (опционально)

**Оценка:** 1-2 часа
